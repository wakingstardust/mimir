# mimir, no-AVX builds

This branch holds only a build workflow. It rebuilds upstream [MakerViking/mimir](https://github.com/MakerViking/mimir) releases for x86-64 CPUs without AVX (an Intel Celeron N5095 NAS), because the stock release statically links an onnxruntime compiled for AVX2 and crashes with an illegal instruction.

The one change is in the root `Cargo.toml`: fastembed drops its default features and uses `ort-load-dynamic`, so the binary loads Microsoft's official onnxruntime from a file named by `ORT_DYLIB_PATH`. It also carries `patches/mcp-recall-json.patch`, which adds an optional `json` flag to the MCP `recall` tool so a caller gets each hit's path, collection and score (the command line already prints most of this), and an optional `project` argument that searches one project by name; the HTTP server also accepts extra Host names from `MIMIR_HTTP_ALLOWED_HOSTS` (for a container name on a private network), and `MIMIR_HTTP_SHARED_ENGINE=1` makes every HTTP session share one engine, so memory stays at one engine on a small host. `MIMIR_HTTP_SNAPSHOT=1` is for serving a read-only index snapshot: recall writes no impression rows and the 120-second WAL checkpoint timer stays off. Without it, the timer's checkpoint counts as another connection's commit, mimir drops its in-memory vector matrix, and on a slow disk the next recall spends tens of seconds re-reading the whole database. Releases are tagged `nas-<upstream tag>-r<PATCH_REV>` and list the onnxruntime version they were tested with.

The workflow runs weekly and on demand (Actions, nas-build, Run workflow, optional tag). It skips tags already released and stops if upstream changes the `ort` pin, since that needs a matching onnxruntime version chosen by hand.

The `main` branch mirrors upstream and is not used.
